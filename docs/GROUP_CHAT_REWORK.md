# 群聊行为改造方案（4.1）

> 目标：让她在群里像个人——被叫了不一定回，回了也可能停，接不上就漏掉。
> 现状问题：67% 的发言不在跟她说话；最长连续 14 轮；敷衍型回复占 0.2%（别人 1.6%）。

---

## 一、保留什么，删什么

### 保留

| 功能 | 说明 |
|---|---|
| **被动通道** | 有人 @ 或引用她 |
| **主动通道** | 活动里"去看群"，看情况说一句 |
| **复读机** | 独立，0 次模型调用 |
| **说说（qzone）** | 不动 |
| **60 秒回看** | 说完话之后回头看一次 |
| **活动** | 含看群、读东西、想事情 |

### 删除

```
每小时回顾（hourlyIntrospect）
冷场搭话（checkQuietGroups）
热群插话（activeJoin）
早晚报（scheduleDailyBrief）
早安（scheduleMorningCatchup）
日记（scheduleDiary）
群级续聊窗口（openWindow(k0, "*")）
认群逻辑（续聊只认当前对话人）
```

## 二、状态机

```
收到 @/引用（某群）
   ↓
这段在跑吗？
   ├ 没在跑，该群无 pending → 立刻开段，t0 = 现在
   ├ 正在跑 → 写入该群 pending（每群最多 1 个，t0 不动）
   └ 没在跑但该群有 pending → 取 t0 最早的
   ↓
等 random(5~15 秒)            ← 人看到提示、解锁、打开软件
   ↓
取上下文（见第三节）
   ↓
她读 → 决定：
   · 回不回
   · 回哪一条
   · 引不引用
   · 要不要补上下文（≤2 次工具调用）
   ↓
打字（按字数）+ 发送（全局打字锁）
   ↓
段结束 → 有 pending 就继续，否则空闲
```

**全局只有一段在跑；同一个群不会攒出第二段，只会合并进同一个 pending。**

## 三、上下文怎么给（游标）

每个群维护两个游标：

```
lastRepliedId   她最后一次回复的那条消息 id
lastSeenId      她最后一次看到的消息 id
```

规则：

```
· 触发消息 id ≤ lastRepliedId → 丢弃，不开段（已经处理过）
· 段内只给"她最后一条回复之后"的消息
· 锚点：她最后说的那句，放在最上面
· 最多 12 条，多了只留最近的
· 每条标：谁说的 / 有没有 @ 她 / 在回谁
· 不管回不回，处理完都推进游标
```

**这解决"上下文里包含她已经回过的内容，她没意识到，于是回第二遍"。**

## 四、段事件的文案（新增，直接可用）

```
【有人在叫你】
群 {群号}｜{发言人} @ 你

target: group:{群号}
messageId: {触发那条的 id}

你刚才说：「{她最后一句}」

之后：
· {时间} {昵称}：{内容}{（id xxx）}
· {时间} {昵称}：{内容}
· …

你在这个群在意的事：{3~5 个关键词}

判断一下：这事跟你有关系吗？
  ① 这是在问我（不是 @ 我，是问我）
  ② 这事我在意
  ③ 我能补一句新的

三条都不占，就不回。不想回就什么都不做，这段就结束了。
回的话，回哪一条、引不引用，你自己定。
```

**注意：`target` 和 `messageId` 必填。**
4.0.18 那次把回复发到别的群，就是因为回看事件漏了这两行。

## 五、收尾规则

### 她的三种收尾（都合法）

```
① 回执式：嗯 / 行 / 哈哈 / 一个表情 / 一个问号
② 沉默式：什么都不做
③ 转移式：换个话题
```

### 对方的收尾信号（代码识别）

以下消息进来时，视为"这段聊完了"，不开段、不开回看：

```
· 低信息量回执：嗯 / 哦 / 好 / 行 / 对 / 是 / 收到 / 谢谢
· 纯表情、纯标点（？/…/。）
· +1 / 1 / 666 / 草 / 笑死 / hhh
· 转发一条什么都不说
```

**判据：长度 ≤3 字且不含疑问；或整条只有表情/标点。**

## 六、回看（60 秒）

```
她发完一条
   ↓
开 60 秒窗口，只盯"她回的那个人"
   ↓
他再说话 → 开新段（还是 5~15 秒）
60 秒没人接 → 该群归零
期间有人 @/引用 → 清掉回看，走新段
```

**不认群：其他人在窗口内说话，不触发。**

---

## 七、漏消息

```
@/引用   → 一定唤醒（不算"没看到"）
普通消息 → 可以漏
同一群 30 秒内 >8 条 → 只读最后 3 条
漏了不补、不提、不道歉
```

## 十二、实施顺序

```
第 1 步（立刻见效，风险低）
  删六项 + 群里只认 @/引用 + 删续聊窗口
  → 发言量应掉到 1/3

第 2 步（结构）
  attention.js 串行段 + 5~15 秒 + 每群一个 pending

第 3 步（精细）
  游标 + 在意清单 + 收尾识别 + 段事件文案
```

**每步单独上线，观察一天再走下一步。**

## 十三、风险

| 风险 | 说明 | 应对 |
|---|---|---|
| 她开始"漏"真人 @ | 段在跑时来的 @ 要排队，可能晚 | 排队取 t0 最早；@ 优先级最高 |
| 段事件漏 target | 会发错群（4.0.18 已踩过） | 渲染必须带 target/messageId，加启动自检 |
| 在意清单不准 | P2 有 56 条、上限 20，抽出来的可能偏 | 先按最近 30 天用过的挑 |
| 活动看群变成巡群 | 她可能每个群都说一句 | 提示明确"看看就走也行"；每群每天软上限 2 次 |
| 删了回顾后记忆变差 | 事实/人物特征记录变少 | 聊天中本来就能存；观察一周 |
